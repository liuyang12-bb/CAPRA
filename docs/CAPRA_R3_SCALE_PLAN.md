# CAPRA R3：规模扩展审查与下一轮方案（未实施、未运行）

本轮保持40GPU/6节点、每类型2节点、每格80单节点任务。集群扩容不等同跨节点训练；以下是静态代码审查和计划，不是规模验证结果。

## 当前限制与可复用模块

|位置|当前范围|每类型4/8节点时|
|---|---|---|

80GPU为每类型4节点（aws4GPU、dgx/rtx8GPU），160GPU为每类型8节点，仍单节点数据并行。大作业跨节点训练将涉及Sia多节点配置、带宽/通信、放置结构、batch、辅助配额分摊和恢复语义，需要另立任务，不能用集群GPU增加冒充支持。

## 最小后续实施与验收

1. 独立新分支，冻结本轮FK/FKR建议后定义多桶GPU可行性和多节点身份算法；不删断言强行跑。先仅每类型4节点，8节点作为后续可选范围，准确登记状态界和最坏成本。
2. GPU可行性用预先固定的小实例与穷举oracle对照；锁/辅助资源借用、满节点、碎片、等价ID、随机输入顺序与平局、缓存隔离、完整见证均需正负例。原40GPU路径先做固定状态兼容回放。
3. 容量与到达强度一起控制。80GPU时作业量/到达率以40GPU的约2倍负载强度作为预注册目标，160GPU为约4倍；必须基于独立来源更长trace或预先声明的多trace叠加，保留源任务ID映射、不要看结果挑有利混合。工作量/应用/GPU需求分布与并发机会同时报告。禁止只扩GPU保留轻负载后宣称扩展性。
4. 最小正式矩阵建议：40/80GPU × original/CM × smart比例、P-K、FK、FKR，共16逻辑格；80GPU负载数量至少160并匹配强度，40GPU80任务。比例CM如继续复用，必须单独预注册严格等价证据；尚不把它算新增实跑。160GPU/320任务不包含在最小矩阵。
5. 验收：全部完成/删失、JCT全体口径、恢复/配额/进度守恒、锁见证、方法隔离；median/P95/max、>5秒、MIP/可行性DP/身份/R/节点配额分项，状态数/节点调用增长和单轮最长时间。预算估算不承诺线性：先独立限定功能验证预算30–45分钟，再据预注册小冒烟wall设置16格总上限180–240分钟、各格15–20分钟。以上仅规划，需用户另行授权；本轮没有扩容代码或规模实验。

## 论文证据清单

现有证据：固定Sia GPU/自适应训练模型、稳定比例强基线、CPU/RAM布局配额优化、有限RAM补充、两个未参与当前开发的同Saturn来源负载与受控响应环境（实际完成情况以R3结果为准）。待补：可比外部资源感知调度、真实或独立可追溯CPU/RAM画像、画像误差/恢复费鲁棒性、多节点规模与控制开销，以及更广负载来源。优先补解释不清的反例与公平基线，不以合成模型中的最大百分比替代泛化证明。

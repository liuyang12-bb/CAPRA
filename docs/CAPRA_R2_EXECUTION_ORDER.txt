五、阶段 A：两个新增方法的精确语义

固定方法规范：
- SIA-P：候选 ['P']；比例配额；原方法。
- CAPRA-Fixed：候选 ['F']；辅助优化；原方法。
- SIA-P-K：候选 ['F','K']；比例配额；新增。
- CAPRA-FK：候选 ['F','K']；辅助优化；新增。
- CAPRA：候选 ['F','K','R']；辅助优化；原完整方法。

这里的标签表示候选构造类型；SIA-P-K 的 F 也必须是比例配额，不能因标签叫 F 而调用辅助优化。

A1. SIA-P-K

复用当前 F 的稳定参考位置，以及当前 K 的位置保留规则、布局构造顺序、GPU可行性检查和扩展规则。
K 尽量保留 GPU 类型、GPU 数量与当前计划兼容的任务位置，恢复锁始终原样保留。
形成完整布局后，每个非锁任务采用其所在节点的实际比例配额：
cpu_i = node.cpu * g_i / node.gpus
ram_i = node.ram * g_i / node.gpus
rho 按同一真实响应函数计算。
不能仅要求 rho 不低于比例下限，而实际给了更多CPU/RAM。

F、K 均不调用 NodeAllocator.solve/layout/pairs/optimize，也不运行 RAM repair。
必要的 baseline/容量预留/验证可使用与原 K 相同的逻辑。

源码陷阱：当前 Placement.retained() 结尾会无条件调用 allocator.layout。必须把 K 布局构造与最终配额策略分离，或者注入明确的配额策略，保证 SIA-P-K 没有偷偷启用辅助优化。

F、K 使用当前同一评分：
Phi = sum_i rho_i * max(0, 1 - delay_i / 180)
保持原 EPS、total_delay、changes 和候选顺序的平局处理。
K 不可行时使用 F，不引入新布局搜索。
记录 K 不可行原因。
精确不生成 R。

A2. CAPRA-FK

同状态下，F 和 K 的布局、配额、可行性、评分与原完整 CAPRA 中对应候选相同。
阶段 A 使用原分配器、原两个初始向量规则、原回收与有限升级循环。
唯一策略区别是候选集合只包含 F、K：
不调用、不构造、不评估 R，不能算完 R 再忽略。
保持同一评分与平局规则；K 不可行时保留 F。

两种新增方法都正常完成动态运行；作业进度可使后续 GPU 决策不同。
不能锁定旧轨迹冒充端到端实验，也不能从既有日志删除 R 决策后生成“新结果”。

六、阶段 B：只增加有界 RAM 剩余容量补充分配

B 的 Fixed、FK、完整 CAPRA 共同使用同一 ram_slack_v1 分配器。
保持 F/K/R 布局构造、GPU计划、CPU优化、费用、H、画像、工作负载和选择规则不变。

推荐采用以下确定的末尾算法：

1. 先完整执行原 NodeAllocator.solve 的两个初始向量比较与选择，得到原算法最终完整可行节点解 out。
2. 以这份原最终解作为不可退化的起点；不要改变原初始向量选择规则，也不要在两个初始解各修一次后重新选择，从而混入其他改动。
3. 对未锁定作业 i，固定 GPU 类型、GPU数量、CPU、节点；其他任务保持当前配额。
4. 按当前完整节点状态计算：
   m_max(i) = min(g_i * max(ram_axis), node.ram - sum_{j!=i} ram_j)
5. 本轮该任务的有限 RAM 候选：
   a. 大于当前 RAM 且不超过 m_max 的原画像 RAM 轴点乘 g_i；
   b. 当前真实上界 m_max。
   去重、检查合法域，不能超过真实可用容量。
6. 只考虑严格正 rho 增益、严格正 RAM 增量的候选。沿用既有数值容差，冻结具体实现。
7. 全节点按以下确定性优先级选择一个更新：
   首先最大 Delta_rho / (Delta_ram / node.ram)；
   再最大 Delta_rho；
   再作业ID；
   再较小 RAM 配额。
   浮点排序和舍入方式在冻结前写入设计，沿用现有规则的精度习惯。
8. 接受一个更新，立即重算整个节点剩余 RAM，再继续。
9. 终止于没有合法正增益候选。

有限步骤上限：
B_node = sum_{unlocked i} count(g_i * original_ram_axis > initial_ram_i) + 1。
这里 initial_ram_i 为进入 RAM 补充阶段时的配额。
解释：RAM只增加；更新到原轴点会跨过一个尚未使用的轴点；若更新到非轴的真实节点容量边界，则耗尽剩余 RAM。画像上限本身已属于轴点。
实现必须验证该界；越界应作为错误记录，不能静默截断后宣称算法正确。
防止容差造成“先超用再反复分配epsilon尾巴”；容量候选来自真实余量，不能靠容量容差多拿资源。

修复必须保持：
- 任务集合、GPU类型/数量、CPU、节点不变；
- 锁定任务完全不变；
- 每个任务的同状态 rho 不下降；
- 原比例性能下限、配额合法域和节点容量成立；
- 原解保留，无收益时严格无操作；
- 每个节点求解，包括 R 中部分布局试算，都使用同一版本规则；
- 缓存与 allocator_mode 隔离，并缓存修复后的最终解；
- RAM平坦、无空闲RAM、已饱和、全锁定等状态不更新配额。

新增步骤独立记为 ram_steps/ram_step_bound/ram_repair_seconds/updates。
不要将它混进旧 upgrades/upgrade_bound，也不要放宽原有限升级循环的断言。
更高同状态 rho 不能作为完整 JCT 一定变好的保证。

十二、分析：用有限对照回答明确问题

复用结果须注明源提交、旧run version、文件路径和hash；不要把复用格算成本轮新执行。

两次动态运行的等待/训练/恢复差只称时间账本分解，不称严格组件因果贡献。

A. 阶段A，三个场景五方法：
1. SIA-P-K vs SIA-P：比例配额下的位置保留收益。
2. CAPRA-FK vs CAPRA-Fixed：辅助优化下的位置保留收益。

C. 必须输出的指标：
- completed/total/status/censored；
- mean/P50/P95/P99 JCT、makespan；
